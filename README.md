# UAC Approval via Discord

Windows の UAC 承認を Discord に申請し、承認者が有効期限付きの管理者パスワードを発行する個人用ツールです。公開 Web サーバーやポート開放は使いません。

## EXE インストーラーを作成する

1. GitHub の **Actions → Build Windows installer → Run workflow** を開きます。
2. ブランチを選んで実行します。
3. 成功した実行の **Artifacts → UacApproval-Windows-x64** をダウンロードして展開します。
4. `UacApproval-Setup-0.2.0-x64.exe` を対象PCで実行します。

インストーラーは **Windows 10/11 x64・管理者権限** が必要です。Python 本体と依存パッケージを同梱するため、Python や PowerShell スクリプトを利用者が用意する必要はありません。専用管理者アカウント `UacApproval`、LocalSystem の Service、期限監視タスクを登録します。Windows の UAC 設定や実行ポリシーの永続設定は変更しません。

生成した EXE は未署名です。発行元の証明書は含みません。ビルド成果物には SHA-256 ファイルも付属します。Actions は手動実行に加えて関連コードの push / PR 時にもビルドを検証します。

## 初回の設定

1. Discord Developer Portal で専用 Bot を作り、本人と Bot だけが閲覧できるチャンネルへ招待します。Bot には View Channel / Send Messages / Attach Files / Read Message History を付与します。Message Content Intent は不要です。Interaction Endpoint URL は設定しません。
2. インストール後、スタートメニューから **UAC Approval** を開きます。
3. **Bot token・チャンネル・承認者を変更** を押し、管理者承認後に Bot token、チャンネル ID、承認者のユーザー ID を入力して保存します。初回は未設定のまま Service が待機します。
4. 必要なプライバシースイッチだけを ON にします。**初期状態では撮影・各情報の共有・自動申請はすべて OFF** です。
5. **承認を申請する** または `Ctrl + Alt + F12` で試します。撮影 OFF でも画像なしの申請ができます。

画面を閉じると通知領域に常駐します。アイコンから設定画面を再表示・終了できます。ログオン時にも自動起動します。Bot token は管理者専用の設定ファイルに保存され、通常ユーザーで動く画面側は読みません。認証情報の変更は Service の再起動を伴い、有効な一時パスワードを失効させます。

## プライバシー

設定は Windows ユーザーごとに保存され、スイッチで個別に制御できます。

| スイッチ | ON の場合 |
| --- | --- |
| スクリーンショット | プライマリモニターを DXGI で継続撮影し、申請時に画像を送信。手動申請時も同じ撮影方式 |
| PC 名 | PC 名を送信 |
| Windows ユーザー名 | ユーザー名を送信 |
| ウィンドウタイトル | 最前面のウィンドウタイトルを取得・送信 |
| プロセス名 | 最前面のプロセス名を取得・送信 |
| 情報取得時刻 | 画像／情報を取得した時刻を送信 |
| 自動検知・申請 | `consent.exe` とデスクトップ切り替えを監視して自動申請 |

撮影 OFF では **撮影 API を呼びません**。撮影用のカメラも作成しません。OFF への反映時には進行中の処理との同期を取り、カメラを解放し、保持画像を破棄します。手動申請でも撮影しません。変更中は画面に表示し、反映完了を待ってから OFF 完了を表示します。送信中の場合は最大約18秒待つ場合があります。

画像はディスクに保存せず、最新の1枚をメモリに保持します。変化がなければ直前のフレームを使用し、JPEG 化は申請時のみ行います。再有効化時に過去の保持画像は再利用しません。画像以外の非共有フィールドは固定文字列「非共有」として送信します。申請理由・申請の存在と Discord の投稿日時は通知に必要な情報として共有されます。すでに送信処理に渡った情報や Discord に届いたメッセージは、スイッチで回収できません。

## 更新と完全アンインストール

更新は最新コードから作ったインストーラーを **再実行** します。認証設定・専用アカウント・各ユーザーのプライバシー設定を保持し、Service と常駐アプリを停止して置き換えます。更新後はスタートメニューから画面を開くか、再ログオンします。

スクリプト経由で更新する場合も EXE を指定できます。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\update.ps1 -InstallerPath C:\Downloads\UacApproval-Setup-0.2.0-x64.exe
```

アプリの **完全アンインストール**、または Windows の **インストールされているアプリ** から削除できます。Service・監視タスク・本ツールが作成した専用アカウント・認証設定・各ユーザーのプライバシー設定・同梱ランタイムを削除し、自動起動の登録値を元に戻します。後から別のプログラムに変更された登録値は上書きしません。Discord に投稿済みの内容と、ダウンロードしたインストーラー／自分の Git チェックアウトは削除しません。

## 制約

- 自動検知はベストエフォートです。通常デスクトップの画像であり、UAC の対象 EXE や署名を証明しません。Secure Desktop 上ではホットキーも撮影もできません。直前フレームが使えない場合は画像なしになります。
- 一時パスワードは期限内に複数回利用できます。特定の EXE に限定する機能や1回使用後の失効はありません。
- 期限監視は Service と毎分の watchdog で行います。Service 障害時は最大約1分の遅れがあり、Windows 停止中は次回起動まで失効処理ができません。既存の昇格済みプロセスを終了する機能ではありません。
- 通常ユーザーの申請情報は信頼できる実行対象の証明ではありません。親PCのマルウェアに対する別のセキュリティ境界にはなりません。

## 実装と開発

Python の既存の期限管理・Discord 処理を維持し、Tk の設定画面、pystray の通知領域、DXGI の撮影制御を追加しました。PyInstaller の onedir EXE と Inno Setup で配布します。Service とデスクトップのランタイムは分離し、Program Files に配置します。今回の要件は Windows API と既存ライブラリで実現できるため、言語の全面変更は行っていません。

`python -m unittest discover -s tests -v` で期限管理・入力検証・撮影停止時の競合と情報フィルタリングを検証します。Windows Actions では凍結 EXE の起動、実際のインストール・上書き更新・Service 起動・アンインストール・登録値の復元も検証します。Discord 接続・実際の UAC 操作・画面キャプチャの実機確認は別途必要です。
